# MT-001 decisions

Engineering defaults below are conservative choices, not claimed measured optima. Performance conclusions and experiment-specific choices are in [RESULTS.md](RESULTS.md) and [PARAMETERS.md](PARAMETERS.md).

| Decision | Alternatives | Selection and rationale | Consequence / limitation | Evidence | Status |
|---|---|---|---|---|---|
| Numerical execution | Reimplement integrator; distribute RHS stages; call existing solver | One unchanged `propagate()` per trajectory | Exact single-trajectory numerical path; no within-trajectory parallelism | `batch.hpp` invokes `propagate.hpp`; scientific bit comparisons in correctness evidence | Final for MT-001 |
| Threading dependencies | OpenMP/TBB; general executor; C++20 workers | Standard `std::jthread`, bounded per-call workers | No new third-party dependency; thread lifecycle paid on each batch | Root CMake exports `Threads::Threads`; raw timings include full call | Final |
| Pool lifetime | Persistent pool; process-global pool; batch-local pool | Batch-local, fixed maximum concurrency | Simple ownership and exception cleanup; short repeated calls may lose to startup | Zero-RHS controls and startup/return measurements | Provisional; persistent pool is an MT-002 experiment |
| Default worker count | Hardware concurrency; fixed parallel default; one | One inline worker | Explicit reproducibility and opt-in concurrency; avoids accidental oversubscription | Default API behavior and permanent tests | Final |
| Default scheduling | Always dynamic; always static; selectable | Static balanced contiguous ranges, explicit dynamic alternative | Static avoids atomic dispatch and keeps adjacent buffers local; adaptive variation may favor dynamic | Both policies measured; no assumed winner | Provisional choice, not tuned optimum |
| API generality | Per-trajectory epoch/options/schedules; shared settings | One epoch, output schedule and integration configuration per batch | Minimal interface; RHS configuration remains trajectory-specific | User allows this restriction; existing solver contract reused | Final for MT-001 |
| Factory ownership | Copy factory; shared RHS; prebuild every RHS | Borrow factory by forwarding reference; create RHS on owning worker | No factory/RHS copy; caller must make concurrent factory captures safe | Move-only and independent-state tests; header lifetime contract | Final |
| Result publication | Completion-order queue; locked append; indexed output | Preallocated indexed trajectory vector | Original order independent of scheduler; no shared output buffer | Full per-field output equality/order checks | Final |
| Failure policy | Fail-fast/cancel; return nullable slots; continue and throw | Continue all trajectories, report lowest failed index after join | Deterministic identity; callers do not receive partial successes; higher errors not aggregated | Factory/RHS multiple-failure and cleanup tests | Final |
| Infrastructure failure | Terminate; wrap as trajectory failure; clean up and rethrow | Stop between trajectories, join started workers, preserve original exception | In-flight propagation is not interrupted; launch-failure injection not part of runtime evidence | RAII `std::jthread` ownership; source review | Final; runtime injection limitation explicit |
| SPICE ownership | Provider per trajectory; shared provider | One stable caller-owned provider | No redundant kernel load/unload/invalidation; global serialization remains | Existing lifecycle implementation; diagnostic invalidation deltas | Final |
| Atmosphere/native locks | Assume reentrancy; remove locks; retain | Retain both native mutexes and CSPICE mutex unchanged | Native calls may dominate scaling; correctness precedes throughput | Native sources contain global state; measured diagnostic contention | Final constraint |
| Atmospheric results | Cache/interpolate density; fresh evaluations | Every requested evaluation calls selected model | No density caching, approximate inputs or hidden model substitution | Existing providers unchanged; RHS/atmosphere/native counts | Final constraint |
| Measurement isolation | Instrument headline timings; infer waits; separate diagnostic binary | Production timings and separately instrumented private adapters | Diagnostic overhead biases absolute timings; wait intervals include timer/lock overhead | Two distinct binaries and links; manifests hash each | Final |
| Scientific acceptance | Re-tune tolerances; impose convergence on CASE-C; compare exact outputs | Existing tolerances; binary64 equality; CASE-C stress-only | Threading cannot hide output differences with tolerance relaxation | Correctness evidence; historical hashes preserve scientific baselines | Final |
| Provenance | SHA only; source-only hashes; full inputs and commands | Starting SHA, committed source revisions, source/dependency/output hashes and exact commands | Documentation commit cannot contain its own hash; manifest identifies source revision plus actual working hashes | `manifest.py`, command records, historical hashes | Final |
| Trace validation protocol | Exhaustive stage traces in every six-hour group; output-only; split checks | Complete six-hour output/state/load comparisons, plus exhaustive 300 s actual-high-worker stage/input comparisons | No weaker numeric acceptance; long-run intermediate stages are not retained/compared. Trace allocations and duplicate preprocessing do not burden long runs | Fully traced attempt timed out at 3600 s without summary; wide traced matrix passed 300/300 | Final for recorded protocol |
| Startup separation | Pretend first-factory marker measures whole pool startup; subtract a microbenchmark; report honest components | Separate all-thread-readiness probe plus production envelopes/per-trajectory propagation series | Probe includes gate overhead and cannot be subtracted from overlapping production startup; no persistent-pool steady-state claim | `startup.cpp`, raw startup samples, total/dispatch/active/join timings | Final |
